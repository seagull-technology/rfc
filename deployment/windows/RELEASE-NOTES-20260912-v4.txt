CHANGES
- Normalize recognized SMTP/SMTPS case in MAIL_SCHEME and a single MAIL_URL
  scheme query value. Only recognized protocol spans change; credentials and
  unrelated URL bytes remain unchanged. Ambiguous duplicate/array/malformed
  scheme parameters and unsupported values fail preflight with redacted output.
- Construct the selected SMTP transport during production validation without
  opening a connection. Check the effective scheme and constructibility again
  after deployment/cache rebuild. This catches the observed scheme error before
  a successful deployment is reported. It does not prove SMTP authentication,
  relay connectivity, or actual delivery.
- Use server validation error keys to select the appropriate production form
  step/tab, highlight affected requirement rows and focus their Fill button.
  Hidden legacy duplicates are ignored. Existing validation and old-input
  preservation remain in effect. The wizard asset uses its existing file-time
  URL version so the changed script is requested after deployment.
