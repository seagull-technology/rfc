PURPOSE
The v4 deployment passed its Windows controller, concurrency and Arabic/English
internal checks. Subsequent public browser testing found two additional issues:
correcting a rejected production synopsis left a hidden legacy field invalid,
and normal production submission returned HTTP 500 after saving Submitted.
The notification audit identified SMTP STARTTLS certificate verification failure.
This release fixes both application failure paths and preserves TLS verification.

CHANGES
- Keep retired inline production fields inside a disabled fieldset. They no
  longer block native validation or duplicate submitted drawer values. Legitimate
  inactive tabs and required drawers retain validation. The wizard counts only
  its outer steps and respects inherited disabled controls.
- Save production/scouting submission state, history, inbox and external jobs
  in one database transaction. Recheck status and ownership under the row lock.
  Independent database mail/SMS jobs retry provider failures without repeating
  submission or preventing other recipients/channels from being processed.
- Preserve message, locale and action URL through queue serialization without
  copying private applicant/record model fields. Queue persistence must use the
  same application database; failed enqueue rolls back the entire submission.
- Include CLI-only public shared-IP rate-limit verification: three disposable
  actors, 20 accepted writes each, then the 61st request rejected. Verified HTTPS,
  real CSRF and stored-value checks remain active; no counter is cleared. The
  helper refuses a nonempty/interfered quota baseline and cleans exact fixtures
  and temporary sessions. It does not test login/OTP or every serving node.
- Include a read-only SMTP trust probe: greeting/EHLO/STARTTLS, validated TLS,
  configured CA locations and public certificate metadata. It does not
  authenticate or send a message, and it does not modify trust configuration.
